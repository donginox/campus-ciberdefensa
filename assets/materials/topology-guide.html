Extraer Campus-red-kit.json antes de transferirlo

La exportación es un sobre JSON con un manifiesto y cuatro archivos de texto; no es un ZIP ni el manifest.json que reciben los scripts. Esta guía también se abre desde Campus con «Leer guía de preparación», antes de extraer el paquete.

En una carpeta de trabajo vacía, guardá la exportación con el nombre exacto Campus-red-kit.json. Abrí una terminal en esa carpeta. Elegí uno de los procedimientos completos siguientes: solo escriben los cuatro archivos permitidos dentro de una carpeta nueva Campus-red-kit, con UTF-8 sin BOM y saltos LF. No ejecutan el contenido del paquete. Si ya existe esa carpeta, usá otra carpeta de trabajo vacía para conservar los archivos anteriores. Si falla una extracción parcial, conservá el error y repetí en otra carpeta vacía.

Windows · PowerShell 5.1 o posterior

Pegá este bloque completo en PowerShell desde la carpeta que contiene la exportación. No hace falta abrir la terminal como administrador.

$ErrorActionPreference = 'Stop'
$source = Join-Path (Get-Location).Path 'Campus-red-kit.json'
$destination = Join-Path (Get-Location).Path 'Campus-red-kit'
$utf8 = New-Object System.Text.UTF8Encoding($false, $true)
if ((Get-Item -LiteralPath $source).Length -gt 7340032) { throw 'Paquete demasiado grande.' }
$kit = [IO.File]::ReadAllText($source, $utf8) | ConvertFrom-Json
$names = @('manifest.json', 'topology-guide.html', 'topology-linux.sh', 'topology-windows.ps1')
if ($kit.manifest.format -cne 'campus-topology-guest-kit' -or $kit.manifest.version -ne 1 -or $kit.files -isnot [array] -or $kit.files.Count -ne 4) { throw 'Formato de paquete incompatible.' }
$contents = @{}
foreach ($item in $kit.files) {
    if ($item.name -isnot [string] -or $names -cnotcontains $item.name -or $contents.ContainsKey($item.name) -or $item.content -isnot [string]) { throw 'Nombre, contenido o archivo repetido no permitido.' }
    $contents.Add($item.name, ($item.content -replace "`r`n?", "`n"))
}
$manifest = $contents['manifest.json'] | ConvertFrom-Json
if (($manifest | ConvertTo-Json -Depth 32 -Compress) -cne ($kit.manifest | ConvertTo-Json -Depth 32 -Compress)) { throw 'Los manifiestos no coinciden.' }
if (Test-Path -LiteralPath $destination) { throw 'Campus-red-kit ya existe. Conserva esa carpeta; usa otra carpeta de trabajo vacia.' }
New-Item -ItemType Directory -Path $destination -ErrorAction Stop | Out-Null
foreach ($name in $names) {
    $bytes = $utf8.GetBytes($contents[$name])
    $stream = [IO.File]::Open((Join-Path $destination $name), [IO.FileMode]::CreateNew, [IO.FileAccess]::Write, [IO.FileShare]::None)
    try { $stream.Write($bytes, 0, $bytes.Length) } finally { $stream.Dispose() }
}
Write-Output 'Archivos extraidos en Campus-red-kit. No se ejecuto ningun script del invitado.'

Linux · Python 3

Guardá este bloque como extraer-campus.py junto a la exportación y ejecutá python3 extraer-campus.py. La extracción tampoco requiere sudo.

import json
from pathlib import Path

source = Path("Campus-red-kit.json")
destination = Path("Campus-red-kit")
names = ("manifest.json", "topology-guide.html", "topology-linux.sh", "topology-windows.ps1")
if source.stat().st_size > 7340032:
    raise SystemExit("Paquete demasiado grande.")
kit = json.loads(source.read_text(encoding="utf-8-sig"))
if not isinstance(kit, dict) or not isinstance(kit.get("manifest"), dict):
    raise SystemExit("Formato de paquete incompatible.")
if kit["manifest"].get("format") != "campus-topology-guest-kit" or kit["manifest"].get("version") != 1:
    raise SystemExit("Version de paquete incompatible.")
files = kit.get("files")
if not isinstance(files, list) or len(files) != 4:
    raise SystemExit("Se requieren exactamente cuatro archivos.")
contents = {}
for item in files:
    if not isinstance(item, dict) or not isinstance(item.get("name"), str):
        raise SystemExit("Archivo invalido.")
    name = item["name"]
    if name not in names or name in contents or not isinstance(item.get("content"), str):
        raise SystemExit("Nombre, contenido o archivo repetido no permitido.")
    contents[name] = item["content"].replace("\r\n", "\n").replace("\r", "\n")
if json.loads(contents["manifest.json"]) != kit["manifest"]:
    raise SystemExit("Los manifiestos no coinciden.")
# mkdir fails if a directory, file or link already exists; never overwrite.
destination.mkdir()
for name in names:
    with (destination / name).open("xb") as output:
        output.write(contents[name].encode("utf-8"))
print("Archivos extraidos en Campus-red-kit. No se ejecuto ningun script del invitado.")

Comprobá que Campus-red-kit contiene manifest.json, topology-guide.html, topology-linux.sh y topology-windows.ps1. Transferí esos cuatro archivos al invitado siguiendo los pasos siguientes. Leé sus scripts y compará UUID y MAC antes de ejecutarlos dentro de cada VM. La extracción puede hacerse en el host; los scripts de preparación se ejecutan únicamente en los invitados propios.

Preparación manual y dependencias

  1. Obtené ISO de Windows y de Debian/Ubuntu/Kali desde fuentes oficiales y revisá licencias y requisitos offline. Campus no descarga ni instala nada. Cada nodo se crea, enciende, apaga y restaura por separado; si uno falla los demás conservan su estado. La topología usa hasta 8 GiB y reserva otros 8 GiB para el host.
  2. Instalá el sistema dentro de cada ventana VirtualBox. Linux necesita Python 3, iproute2, nftables, systemd, shadow-utils y, para el salto, OpenSSH Server. Windows necesita PowerShell con módulos NetTCPIP/LocalAccounts y OpenSSH Client para la campaña. Si faltan, prepará medios oficiales offline; los scripts no ejecutan apt ni descargan paquetes.
  3. Exportá el paquete una vez creados los tres nodos y extraelo con el procedimiento anterior. Transferí los archivos mediante un medio extraíble de tu control, por ejemplo un ISO de datos creado manualmente y montado como DVD dentro de VirtualBox. No habilites carpetas compartidas, portapapeles, NAT, puente ni host-only. Reponé el DVD original o dejalo vacío antes de usar controles de Campus, porque se verifican sus rutas. Compará manifest.json con UUID DMI y MAC dentro del guest. No edites el manifiesto para saltar la guardia: recreá y volvé a exportar si cambió la identidad.
  4. En Linux verificá cat /sys/class/dmi/id/product_uuid, cat /sys/class/dmi/id/product_name y ip -br link. Ejecutá sudo bash topology-linux.sh manifest.json router o server según rol. En Windows comprobá Get-CimInstance Win32_ComputerSystemProduct y Get-NetAdapter -Physical; leé el script y ejecutalo desde PowerShell administrador con .\topology-windows.ps1 -ManifestPath .\manifest.json. Respetá la política de ejecución de tu VM; no cambies la del host.
  5. Los scripts hacen cambios por pasos y pueden fallar parcialmente. Conservá el error, revisá dentro del guest o restaurá la base propia de ese nodo y repetí. No hay rollback de grupo. La configuración Linux de IP es temporal: tras reiniciar, configurá manualmente esas mismas IPs por MAC con el gestor de red de tu distribución, sin gateway. La tabla nft es temporal: guardá/reaplicá solo inet campus_lab dentro del guest, conservando las otras tablas. No vacíes el ruleset global. Otras reglas existentes pueden bloquear el servicio: diagnosticá primero.

SSH y servicio

En salto asigná una contraseña propia con sudo passwd campus-jump. El script crea un fragmento para sshd_config.d, exige su Include, valida sintaxis y deja el reinicio del servicio para vos. Antes de reiniciar, verificá que sudo sshd -T -C user=campus-jump,host=campus,addr=10.78.10.10 muestra allowtcpforwarding local y permitopen 10.78.20.20:8080. Si hay Match/Include anteriores que cambian el resultado, corregilos solo dentro de esta VM. Reiniciá ssh.service o sshd.service según tu distribución y verificá su escucha en 22.

Servidor ejecuta campus-web.service como campus-web, sin login, con archivos ficticios root:campus-lectores y permisos 750/640. Solo el salto puede acceder a 8080. Agregá manualmente una cuenta ficticia al grupo campus-lectores para probar lectura; comprobá que no puede escribir. En Windows compará Get-LocalUser e icacls C:\CampusLab usando campus-alumno y una cuenta administradora.

Windows: ping 10.78.10.1
Salto: ping 10.78.20.20; curl http://10.78.20.20:8080
Windows: ssh -N -L 127.0.0.1:18080:10.78.20.20:8080 campus-jump@10.78.10.1
Windows: abrir http://127.0.0.1:18080

El puerto 18080 se abre en loopback dentro de la VM Windows por acción manual del alumno, no en el host. Sin túnel no debe responder. Probá un destino/puerto alternativo de estos mismos nodos para comprobar el rechazo de PermitOpen; cerrá SSH y repetí la prueba. El router no enruta IP entre segmentos: el salto autorizado es el túnel SSH.

Evidencia y límites

Registrá fecha, IP, identidad, comando, resultado esperado, salida observada y diferencia. No guardes contraseñas. VM en ejecución no significa SO instalado, servicios listos ni campaña aprobada. Campus no observa las pruebas del invitado. Una PC física con Kali no puede unirse a estas redes internas VirtualBox: usá una VM Linux propia en este mismo host. Las redes internas aíslan perfiles pero no son una garantía para ejecutar malware; trabajá solo con datos ficticios y sistemas propios.

Referencias: redes VirtualBox, sshd_config, cadenas nftables, OpenSSH en Windows.
