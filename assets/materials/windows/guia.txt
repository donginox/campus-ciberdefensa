WINDOWS PARA INTEGRAR SISTEMAS OPERATIVOS Y CIBERSEGURIDAD

Esta guía trabaja Windows como un sistema que tenés que comprender, administrar y diagnosticar. Kali es otro entorno del recorrido; las competencias de Windows requieren estudiar Windows y practicar en él. El objetivo es conectar hardware, procesos, memoria, archivos, redes, identidad y registros para que puedas explicar un caso completo.

El contenido es una ampliación docente propia, preparada el 30 de octubre de 2026. Se relaciona con los temas constatados del programa de Sistemas Operativos I y las guías accesibles de Sistemas Operativos II; no se atribuye a los PDF de Windows que siguen pendientes de lectura en el campus. No es una guía exhaustiva de toda la administración empresarial de Microsoft. Sí cubre la base de Windows necesaria para esta integración anual, junto con seis prácticos y puntos de continuación.

ENTORNO Y FORMA DE TRABAJO

Usá Windows 11 en un equipo propio o una VM de práctica. Si tenés otra versión soportada o un laboratorio alojado, registrá versión y edición: los nombres de pantallas, módulos y funciones pueden variar. Una VM permite probar cambios de cuentas y políticas con una instantánea previa, pero una instantánea no reemplaza un backup separado. En un equipo administrado por una institución no se cambian sus políticas para completar una práctica.

Los ejemplos se diseñaron para Windows PowerShell 5.1, disponible mediante powershell.exe en Windows. PowerShell 7 usa pwsh.exe, se instala por separado y puede coexistir. La mayoría de los conceptos de lenguaje es compartida, pero el motor, módulos y algunos comportamientos difieren. Los módulos de red, Defender o administración pueden depender de Windows y de compatibilidad; un error de módulo no se interpreta como falta de comprensión. Antes de ejecutar, mirá $PSVersionTable y Get-Command para comprobar el comando concreto. No hace falta instalar PowerShell 7 para empezar. [W1]

Abrí Windows PowerShell sin elevar como administrador. Los prácticos iniciales usan tu cuenta normal, lecturas acotadas y archivos ficticios. Cuando una lectura no está permitida, registrá el límite. No se resuelve un acceso denegado elevando todo automáticamente. Los nombres locales o datos de tu equipo pueden ser privados: entregá solo la evidencia necesaria del laboratorio.

Para los ejemplos, los bloques están identificados como powershell; no se pegan en Bash ni en CMD. En PowerShell una barra vertical transmite objetos entre cmdlets, no solamente líneas de texto. Get-Help muestra la ayuda local y Get-Member permite inspeccionar propiedades y métodos. Format-Table y Format-List se usan al final, para presentar; si formateás antes de filtrar o exportar, podés perder el tipo de información que necesitabas.

QUÉ HACE WINDOWS DESDE QUE ARRANCA

La computadora comienza ejecutando firmware. En una instalación moderna, UEFI participa en localizar y arrancar el cargador. Luego se cargan componentes del sistema, controladores y servicios hasta ofrecer inicio de sesión y aplicaciones. Un fallo antes de iniciar sesión puede estar en una etapa distinta de un problema de una aplicación ya abierta: diagnosticar consiste en ubicar el límite donde deja de funcionar.

Secure Boot ayuda a verificar componentes autorizados en la cadena de arranque; Trusted Boot y otras protecciones intervienen en etapas posteriores. Un TPM puede proteger claves y mediciones. Son piezas relacionadas, no equivalentes. Ninguna implica por sí sola que todos los archivos del usuario estén cifrados o que cualquier programa sea confiable. Para esta unidad se observan conceptos y estado; no se cambia firmware ni se desactivan protecciones para practicar. [W2]

El kernel coordina ejecución, memoria y acceso a recursos. El modo usuario limita el acceso directo de las aplicaciones a partes críticas del sistema; las llamadas al sistema permiten solicitar servicios controlados. Un driver es código que participa en la interacción con hardware u otros componentes. Una falla de una aplicación no tiene el mismo alcance que un componente privilegiado defectuoso. El escritorio gráfico y la shell no son el kernel.

La arquitectura de 32 o 64 bits influye en instrucciones, direcciones y compatibilidad. No deduzcas la memoria disponible de un proceso contando solamente la RAM instalada. Tampoco significa que todo programa en un Windows de 64 bits sea de 64 bits. La compatibilidad de aplicaciones depende además de bibliotecas, interfaces y edición. Para la cursada importa explicar la diferencia entre ancho de direcciones, espacio virtual, memoria física y límites del sistema.

MEMORIA, CPU, PROCESOS E HILOS

Un proceso agrupa recursos y un contexto de ejecución: código, espacio de direcciones, identificador, contexto de seguridad y objetos abiertos, entre otros. Un hilo es una unidad de ejecución dentro del proceso que puede planificarse; varios hilos comparten recursos del proceso. Tener muchos hilos no garantiza mejor rendimiento: pueden esperar disco, red o una sección crítica. [W3]

La memoria virtual es un espacio de direcciones que el sistema traduce a ubicaciones físicas o a respaldos correspondientes. La paginación organiza ese manejo en páginas; no hay que confundirla con el archivo de paginación. El working set describe páginas residentes asociadas a un proceso en un momento. Un número alto de memoria no demuestra una fuga: necesitás observar tendencia, carga, límites y comportamiento. CPU alta y memoria alta son señales diferentes. [W4]

En Administración de tareas podés observar procesos y rendimiento; el Monitor de recursos agrega detalle. Compará mediciones sobre el mismo intervalo y con la misma unidad. CPU acumulada de un proceso no es porcentaje instantáneo. Identificadores se reutilizan al terminar los procesos; por eso para actuar sobre un proceso propio también conviene registrar su momento de inicio.

Un servicio es una aplicación o componente administrado por el sistema de servicios, con una identidad y ciclo de vida propios. No todo proceso es un servicio ni toda tarea automática es un servicio. El Programador de tareas ejecuta acciones según desencadenadores, condiciones y cuenta. Un servicio detenido puede estar funcionando según su configuración; una tarea que existe no prueba que se ejecutó. Para investigarlos se relacionan configuración, estado, desencadenador, cuenta, último resultado y registros.

Ejemplo conceptual: una aplicación depende de un servicio que espera una base de datos. Reiniciar la interfaz puede no corregir nada. Antes de actuar preguntás qué proceso escucha, si su dependencia está disponible, qué identidad usa y qué registro corresponde al intento. Reiniciar o terminar componentes sin observar primero puede borrar el síntoma y afectar otras tareas.

ARCHIVOS, RUTAS Y REGISTRO

Una partición o volumen no es lo mismo que un directorio. Una letra como C: es una forma de acceder a un volumen; la ruta identifica un objeto dentro de un espacio de nombres. La extensión ayuda a asociar un archivo con un programa pero no verifica su formato real. Mostrar extensiones en el Explorador ayuda a detectar nombres engañosos; esa opción no analiza el contenido ni determina si es seguro.

NTFS ofrece metadatos, descriptores de seguridad, permisos y mecanismos de consistencia. Su registro transaccional del sistema de archivos no es un historial completo del contenido del usuario ni una copia de seguridad. Un volumen que conserva consistencia estructural puede contener archivos borrados o datos incorrectos. FAT/exFAT no ofrecen el mismo modelo de permisos NTFS; antes del práctico de ACL comprobamos el tipo de sistema de archivos. [W5]

El Registro de Windows almacena configuración mediante claves y valores. No es una base de datos SQL ni una única lista de programas maliciosos. Una ruta de configuración tiene contexto: equipo o usuario, programa, permisos y momento del cambio. Aprender a inspeccionarlo no exige editarlo. En este módulo no modificamos claves ni importamos archivos .reg.

Una ruta puede apuntar a un vínculo o punto de reanálisis. Cuando una tarea modifica permisos o escribe archivos, conviene comprobar el objeto resuelto y el alcance. Por eso usamos una carpeta nueva con nombre aleatorio y no ejecutamos cambios recursivos sobre rutas generales. LiteralPath evita interpretar comodines: sirve para tratar el nombre como dato.

IDENTIDADES, GRUPOS, UAC Y MÍNIMO PRIVILEGIO

Autenticación comprueba una identidad declarada mediante controles; autorización decide qué acciones permite a ese contexto. Windows identifica principales mediante SID. Un nombre visible puede cambiar o repetirse en autoridades distintas: EQUIPO\ana no es necesariamente DOMINIO\ana. La pertenencia a grupos y los privilegios forman parte del contexto de acceso. Ser propietario de un archivo tampoco es sinónimo de tener cualquier permiso operativo en todos los recursos. [W6]

Una cuenta local se administra en ese equipo. Una cuenta Microsoft y una identidad institucional tienen otros servicios y mecanismos de gestión. Antes de cambiar una cuenta, determiná de qué autoridad depende. Crear usuarios, unir un equipo a un dominio o modificar contraseñas no es parte de los ejercicios sobre tu equipo real.

UAC permite que tareas ordinarias y acciones elevadas se ejecuten con contextos diferentes. Un usuario miembro de Administradores no necesariamente ejecuta cada aplicación con el token elevado. La elevación requiere una interacción según el usuario y la política. Un prompt de UAC no es un análisis de seguridad del código: aceptar sin comprender sigue siendo una decisión riesgosa. Mantener la tarea con los permisos que necesita reduce el alcance de un error. [W7]

En un entorno empresarial, los grupos permiten asignar permisos por función. Dar permisos a un grupo no elimina la necesidad de revisar quién lo integra y quién puede modificarlo. Una cuenta de servicio necesita derechos para una función concreta, registro de actividad y gestión de su ciclo de vida; no debe recibir privilegios generales por comodidad.

NTFS, HERENCIA Y RECURSOS COMPARTIDOS

La DACL contiene entradas de control de acceso para principales y derechos. Hay entradas explícitas y heredadas; la herencia transmite reglas desde un contenedor a hijos según sus indicadores. Un permiso de un grupo puede seguir concediendo una acción aunque agregues otra entrada de lectura para el usuario. Agregar una regla no demuestra que redujiste el acceso efectivo. [W6, W8]

En el Explorador: Propiedades, Seguridad y Opciones avanzadas permiten observar propietario, herencia y entradas. La herramienta de acceso efectivo puede ayudar, pero tiene condiciones y no reemplaza probar el acceso con el contexto correcto en una VM de práctica. Evitá resumir el algoritmo como «Deny siempre gana» sin considerar orden, herencia, grupos, derechos y contexto.

Al acceder por un recurso compartido de red se evalúan capas adicionales: identidad, permisos del recurso compartido y del sistema de archivos, entre otras. Un permiso amplio en una capa no elimina una restricción de la otra. El acceso local a un archivo no atraviesa del mismo modo la autorización del recurso SMB. Si un usuario lee localmente pero no por red, el diagnóstico tiene que recorrer esas capas, junto con conectividad y nombres.

Un acceso denegado se investiga identificando usuario/grupos, recurso, operación exacta, herencia, reglas y ruta de acceso. Dar Full Control a Everyone puede ocultar la causa y ampliar acceso. Tampoco se necesita ensayar esa modificación para comprenderla.

REDES Y SEGURIDAD DEL EQUIPO

Windows usa los mismos principios IP, TCP/UDP y DNS estudiados en Telecomunicaciones. Una interfaz tiene configuración; una ruta define un recorrido; un puerto permite diferenciar extremos de transporte. Nombre, dirección y puerto son datos distintos. Poder resolver un nombre no demuestra que el servicio esté escuchando. Una conexión TCP exitosa tampoco demuestra que la aplicación responda correctamente.

Get-NetIPConfiguration muestra la configuración de interfaces; Get-NetRoute permite observar rutas. Usá filtros y registrá solamente la interfaz necesaria. Resolve-DnsName consulta resolución DNS con opciones específicas; la resolución que hace una aplicación puede incluir cachés y otros mecanismos. Para un primer laboratorio sin salir del equipo usamos 127.0.0.1 y un puerto dinámico.

Get-NetTCPConnection relaciona dirección, puerto, estado y proceso propietario. El resultado es una fotografía: una conexión breve puede desaparecer antes de medirla. Test-NetConnection permite una prueba TCP concreta. Diferenciá esa comprobación de ICMP, de una consulta DNS y de una respuesta HTTP. [W9, W10]

El firewall tiene perfiles y reglas que dependen de política y contexto. Consultar Get-NetFirewallProfile con ActiveStore ayuda a observar configuración efectiva de perfiles. Un perfil no es un inventario de todas las decisiones posibles: importan reglas, interfaces, estado, aplicaciones y políticas. Este módulo no desactiva el firewall ni crea excepciones globales. Si una práctica necesita permitir tráfico entre VMs, se diseña una regla específica dentro del entorno de laboratorio y se prueba por separado. [W11]

REGISTROS, DEFENDER Y ACTUALIZACIONES

Event Viewer organiza registros por canales y proveedores. ID sin proveedor y canal puede ser ambiguo. Una investigación conserva timestamp con zona, equipo, proveedor, ID, RecordId y datos relevantes. El texto de Message puede variar por idioma y versión; por eso una búsqueda robusta aprovecha campos estructurados. Un evento no demuestra por sí solo intención o autoría.

Get-WinEvent admite filtros por tabla hash, XPath o consultas XML. Filtrar por canal y tiempo antes de recuperar reduce volumen. Security puede requerir permisos que tu sesión no tenga y el evento puede depender de que una auditoría estuviera habilitada. Ausencia de un evento no demuestra ausencia de la acción. No se habilitan auditorías globales ni se borran registros para completar esta clase. [W12]

4624 representa un inicio de sesión exitoso y 4625 un fallo en el contexto documentado del proveedor de auditoría. Hay que interpretar el tipo de inicio de sesión, la cuenta, el equipo donde se registró y otros campos. No todos los intentos se reflejan en cualquier equipo. Para practicar sin usar registros privados, este paquete trae JSONL sintético, que no es una exportación EVTX. El evento 4104 del conjunto representa contenido de un bloque PowerShell registrado; su generación depende de la configuración de registro y no se asume habilitada en tu PC. [W13, W20]

Windows Security reúne distintas protecciones. Get-MpComputerStatus consulta estado de antimalware cuando el módulo está disponible; una propiedad aislada no certifica que el equipo esté limpio. En equipos con otro producto o políticas institucionales puede cambiar el modo operativo. No se fuerza su activación ni se deshabilita protección para realizar un ejercicio. [W14]

Actualizar reduce exposición conocida, pero requiere considerar reinicios, compatibilidad y recuperación. La buena práctica de estudio es identificar versión, estado, fuente de actualización y si hay reinicio pendiente mediante la interfaz, y explicar cómo probar un cambio en una VM. No se instala una actualización ni se cambia una política del equipo real como parte de estos prácticos.

BACKUP, RESTAURACIÓN Y CIFRADO

Un backup sirve cuando puede restaurarse lo necesario dentro del tiempo y pérdida de datos tolerables. Sin una prueba de recuperación, solamente comprobaste que se creó algún archivo. Una copia en el mismo disco y accesible con la misma cuenta puede perderse junto con el original. La estrategia real considera otras ubicaciones, versiones, acceso y copias protegidas.

RPO expresa cuánta pérdida de datos se tolera, medida como distancia temporal hacia el último punto recuperable. RTO expresa el tiempo objetivo de recuperación del servicio. Una restauración de archivos puede no recuperar una aplicación completa: también hacen falta configuración, permisos, dependencias y una prueba funcional. En el práctico hacemos una restauración pequeña a otra carpeta para entender el método sin tocar archivos reales.

Un hash detecta diferencias de bytes frente a una referencia confiable; no cifra y no demuestra quién hizo el cambio. Si Windows PowerShell 5.1 y PowerShell 7 crean texto con codificaciones o BOM diferentes, los bytes pueden diferir aunque una pantalla se parezca. Por eso se compara el archivo existente y se explicita codificación al crear datos. [W15]

BitLocker protege volúmenes frente a escenarios de acceso no autorizado, especialmente cuando el sistema está fuera de línea. No reemplaza permisos ni impide que una sesión autorizada lea sus archivos ya desbloqueados. Su administración completa se ofrece según edición; la función Device Encryption también puede estar disponible en equipos Home que cumplan requisitos. No confundas las interfaces o concluyas que todo Home carece de cifrado. Antes de cualquier cambio real se debe comprender la recuperación de claves; no actives, suspendas ni descifres unidades por este ejercicio. [W16, W17]

ENTORNO EMPRESARIAL: AD DS, DOMINIO, GPO Y ENTRA

AD DS organiza objetos como usuarios, equipos y grupos en un directorio y ofrece autenticación y administración relacionadas. Un controlador de dominio no es lo mismo que una PC cliente que participa del dominio. Dominios, unidades organizativas, grupos y políticas tienen funciones diferentes; aprender sus nombres no alcanza para diseñar permisos. [W18]

Group Policy permite aplicar configuraciones según alcance y procesamiento. Una política local y una de dominio no equivalen a una preferencia elegida por el usuario en Configuración. Para diagnosticar una opción administrada necesitás entender quién controla la política, a quién se aplica y cómo observar su resultado. No se «corrige» una restricción institucional editando el Registro.

Microsoft Entra ID es un servicio de identidad orientado a escenarios de nube, con roles, aplicaciones y formas de gestión propias. No es simplemente un controlador de dominio en Internet, y unir un dispositivo a Entra no es lo mismo que unirlo a AD DS. Pueden coexistir en arquitecturas híbridas. En este módulo se estudia la comparación y se razona sobre identidades; montar un dominio y políticas de prueba sería una continuación práctica en VMs con licencias y recursos disponibles. [W19]

Objetivo: observar la diferencia entre reglas heredadas y explícitas, aplicar una DACL acotada y restaurar la original. Tiempo inicial: 90–120 min. Usar un volumen NTFS. No se cambia una carpeta existente de trabajo o del sistema.

En el Explorador observá el sistema de archivos de la unidad donde está tu carpeta temporal. Si no es NTFS o no permite ACL, registrá el límite y usá una VM NTFS para esta parte. Los conceptos se pueden estudiar, pero no se cuenta una ACL aplicada sobre otro sistema de archivos como práctica equivalente.

```powershell
if (-not $RaizWindowsLab -or -not (Test-Path -LiteralPath $RaizWindowsLab -PathType Container)) {
    throw 'Falta el montaje W1 en esta sesión.'
}

if (-not $RaizW2.StartsWith($TemporalW2 + '\CursoWindows-', [StringComparison]::OrdinalIgnoreCase) -or
    (Split-Path -Leaf $RaizW2) -notmatch '^CursoWindows-[0-9a-f]{32}$') {
```

Antes de continuar, anotá las entradas y comprobá en la interfaz cuáles son heredadas. El bloque siguiente crea reglas de control para tu SID actual, SYSTEM y Administradores; no prueba exclusividad frente a administradores. Tampoco cambia grupos ni cuentas. El propósito es estudiar una DACL explícita en la carpeta nueva. [W8]

```powershell
$SidActualW2 = [Security.Principal.WindowsIdentity]::GetCurrent().User.Value
$AclNuevaW2 = [Security.AccessControl.DirectorySecurity]::new()
$AclNuevaW2.SetAccessRuleProtection($true, $false)
$HerenciaW2 = [Security.AccessControl.InheritanceFlags]'ContainerInherit,ObjectInherit'
foreach ($SidTextoW2 in @($SidActualW2, 'S-1-5-18', 'S-1-5-32-544')) {
    $ReglaW2 = [Security.AccessControl.FileSystemAccessRule]::new(
        [Security.Principal.SecurityIdentifier]::new($SidTextoW2),
        [Security.AccessControl.FileSystemRights]::FullControl,
        $HerenciaW2,
        [Security.AccessControl.PropagationFlags]::None,
        [Security.AccessControl.AccessControlType]::Allow)
    $null = $AclNuevaW2.AddAccessRule($ReglaW2)
}
Set-Acl -LiteralPath $CarpetaAclW2 -AclObject $AclNuevaW2 -ErrorAction Stop
Get-Acl -LiteralPath $CarpetaAclW2 | Format-List Owner, AreAccessRulesProtected, AccessToString
```

PRÁCTICO W3 — UN PROCESO PROPIO Y SUS DIFERENCIAS CON SERVICIOS Y TAREAS

Objetivo: observar un proceso controlado y terminar únicamente ese proceso; distinguirlo de un servicio o una tarea. Tiempo inicial: 60–90 min. No se detienen componentes del sistema.

```powershell
$EjecutableW3 = Join-Path $env:SystemRoot 'System32\WindowsPowerShell\v1.0\powershell.exe'
if (-not (Test-Path -LiteralPath $EjecutableW3 -PathType Leaf)) { throw 'No se encontró Windows PowerShell.' }
$ProcesoW3 = Start-Process -FilePath $EjecutableW3 -ArgumentList '-NoProfile', '-Command', 'Start-Sleep -Seconds 600' -WindowStyle Hidden -PassThru
$InicioW3 = $ProcesoW3.StartTime
$IdW3 = $ProcesoW3.Id
Get-Process -Id $IdW3 | Select-Object Id, ProcessName, StartTime, CPU, WorkingSet64
```

Buscá solamente ese PID en Administración de tareas. Contrastá memoria y CPU con la definición de la métrica; no sumes campos diferentes como si fueran equivalentes. No se necesita abrir todos los procesos ni compartir sus nombres.

Para cerrar la prueba se vuelve a comprobar identidad y momento de inicio:

```powershell
$ActualW3 = Get-Process -Id $IdW3 -ErrorAction SilentlyContinue
if ($null -eq $ActualW3) {
    Write-Output 'El proceso de prueba ya terminó; no se envió una señal.'
} elseif ($ActualW3.ProcessName -eq 'powershell' -and $ActualW3.StartTime -eq $InicioW3) {
    Stop-Process -InputObject $ActualW3 -ErrorAction Stop
} else {
    throw 'La identidad no coincide; no se termina ningún proceso.'
}
```

Guiado: consultá Get-Service -Name EventLog para observar ese servicio sin cambiarlo. Abrí el Programador de tareas, elegí una tarea integrada de Microsoft visible y leé acción, desencadenador y cuenta, sin ejecutarla ni modificarla. Si el equipo restringe esa lectura, registralo.

Reto independiente: prepará una tabla con programa, proceso, hilo, servicio y tarea programada; agregá un ejemplo propio para cada uno. Explicá por qué un PID por sí solo no basta y qué necesitás para atribuir un puerto a ese proceso. Proponé cómo observarías una espera por red sin terminarlo.

Evidencia: PID de prueba, inicio, campos interpretados y comprobación de cierre; tabla conceptual. Rúbrica 10: control del proceso 3, métricas 2, distinciones 3, diagnóstico 2. Si ya terminó, esa observación es válida: no hay que escoger otro PID.

PRÁCTICO W4 — TCP LOCAL, ESTADO Y FIREWALL

Objetivo: relacionar escucha, conexión y proceso sin exponer un servicio a la red. Tiempo inicial: 60–90 min. El puerto lo asigna el sistema y la escucha se vincula solo a loopback.

```powershell
$EscuchaW4 = [Net.Sockets.TcpListener]::new([Net.IPAddress]::Loopback, 0)
try {
    $EscuchaW4.Start()
    $PuertoW4 = $EscuchaW4.LocalEndpoint.Port
    Write-Output "Puerto temporal de prueba: $PuertoW4"
    Get-NetTCPConnection -LocalAddress '127.0.0.1' -LocalPort $PuertoW4 -State Listen |
        Select-Object LocalAddress, LocalPort, State, OwningProcess
    Test-NetConnection -ComputerName '127.0.0.1' -Port $PuertoW4 -InformationLevel Detailed
} finally {
    $EscuchaW4.Stop()
}
```

El ejemplo comprueba TCP; no implementa HTTP ni entrega una página. El bloque finally cierra la escucha aunque una consulta falle. Si tu módulo no está disponible en PowerShell 7, probá la lectura en Windows PowerShell 5.1; no abras un puerto permanente ni desactives el firewall para adaptarlo.

Guiado: observá los perfiles sin modificar nada:

```powershell

```

Evidencia: solo dirección/puerto de laboratorio y proceso relacionado; explicación de las tres capas. Rúbrica 10: TCP 3, proceso 2, capas de diagnóstico 3, lectura de políticas 2. Error frecuente: tomar ping o TCP exitoso como prueba de que toda la aplicación funciona.
