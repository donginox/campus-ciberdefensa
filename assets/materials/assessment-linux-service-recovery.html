Caso D · Servicio Linux y reversión de permisos

Consigna original de Campus. Este material no incluye soluciones. La orientación se consulta en Evaluación después de guardar la entrega.

Situación

Un servicio ficticio de informes dejó de leer su entrada tras un cambio de permisos. Debés localizar la dependencia de recorrido sin resolverlo con root o permisos globales. Reproducí la variante elegida con archivos inocuos en el servidor Linux propio y compará una corrección mínima con la reversión.

Línea de base

Registrá distribución guest, usuario efectivo del servicio, permisos de cada directorio, hash del archivo ficticio y estado previo. El ejemplo es texto sintético para reconstruir manualmente; una VM sin Linux instalado no permite verificarlo.

Alcance

Solo la carpeta /srv/campus-report de tu guest Linux propio y una unidad de laboratorio creada para este caso. No cambiar /etc ni servicios ajenos, ejecutar contenido del alumno en el host ni aplicar chmod recursivo global.

Entregable

Árbol de permisos y propietario antes/después, identidad efectiva, error reproducible, prueba de lectura mínima y verificación de que otro usuario ficticio sigue excluido; hashes del archivo antes/después, registro del cambio y procedimiento probado de recuperación. Explicá si el fallo es de recorrido, lectura u otro control y qué evidencia lo refutaría.

Variantes

Elegí A o B antes de empezar y registralo. Repetir otra variante del mismo caso se conserva como caso repetido; no se presenta como una muestra independiente nueva.

Rúbrica visible

  • Identifica el permiso requerido en cada componente de la ruta.
  • Contrasta error y resultado con la misma cuenta efectiva del servicio.
  • No propone root ni 777 como solución; conserva denegación al usuario de control.
  • Valida recuperación y contenido sin confundir arranque exitoso con integridad.
